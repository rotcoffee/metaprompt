# 목표

BM25 상위 후보를 재랭킹하는 새 방법과, 그것이 기존 재랭킹보다 나은지 입증하는 실험 코드·리포트를 만들어줘. **MiniLM 교차 인코더 재랭킹 (BEIR 서브셋 nDCG@10)** 을 넘어서는 수준이어야 한다.
Python 3.11, GPU 1장 이하, 공개 데이터셋만. 결과는 `report.md` 와 재현 커맨드 하나로 남긴다.

"동작하는 수준"이 아니라 "MiniLM 교차 인코더 재랭킹과 나란히 놓아도 밀리지 않고, 같은 nDCG@10 에서 GPU 시간이 절반 이하라는 점에서는 앞서는 수준"이 목표다.
이 파일은 명세가 아니라 **바닥**이다 — 적히지 않은 것도 주제를 들은 사용자가 기대하면 만들고, 적힌 수치는 하한이다.
기준선을 약하게 두고 이긴 결과, 시드 하나로 낸 결과는 실패다.

## 기준점 상세

- 기준선: BM25 nDCG@10 — SciFact 0.665 / NFCorpus 0.325 / FiQA 0.236 (BEIR 공식 설정, k1=0.9 b=0.4) (예시 수치)
- 넘을 대상: 같은 조건의 MiniLM 교차 인코더 재랭킹 보고값 SciFact 0.68대, 후보 100건 고정 (예시 수치)
- MiniLM 재랭킹은 질의 난이도와 무관하게 후보 100건을 전부 채점한다 — 비용이 질의 수에 선형 (출처 미확인)
- 지표 정의: pytrec_eval 의 ndcg_cut_10, 표준 qrels, 테스트 분할만 평가
- 알려진 함정: 학습 데이터(MS MARCO)와 평가셋의 문서 중복, 후보 수(100 vs 1000)에 따른 비교 불공정

## 실행 예산 (route: creative · tier: max)

- 메인 세션 effort **high** · model **opus** — `claude --model opus --effort high` 로 시작한다 (도중에는 `/effort high`). 세션 모델이 다르면 시작하지 말고 알린다. xhigh·max 는 이득을 실측하지 않았으면 쓰지 않는다.
- 라운드 상한 **5**. 팬아웃 서브에이전트는 동시에 최대 **5개**.
- 역할 — effort 는 에이전트 정의 frontmatter 로만 지정된다 (Agent 호출에는 effort 가 없다). 세션 **시작 전에** `python3 <metaprompt>/scripts/agents.py <이 파일>` 이 아래 표로 `.claude/agents/mp-*.md` 를 만든다. 정의가 로드되지 않았으면 호출에 model 만 지정하고, effort 가 세션값을 상속했다고 판정문에 적는다.

  | 역할 | 정의 | model | effort | 맡는 일 |
  |---|---|---|---|---|
  | 메인 세션 (오케스트레이터·빌더) | — | opus | high | 방법 설계와 파이프라인 |
  | 검증자 | mp-verifier | opus | high | 매 라운드 새 컨텍스트에서 재현·반증 |
  | 심사자 | mp-judge | opus | medium | 리포트 블라인드 비교 |
  | 워커 | mp-worker | sonnet | low | 데이터셋·지표 검증·그림 |

- 기능 스위치:
  - agent teams **ON** — 발산 단계에만. 후보 방법 3개(질의 난이도 적응 후보 수 · 증류 소형 채점기 · 조기 종료 캐스케이드)를 팀원이 각자 시안으로 내고 서로 반박한 뒤 하나를 고른다. 구현은 단일 빌더. `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` 로 시작한다.
  - Workflow **ON** — 증거 수집에만. 3셋 × 3시드 재현과 반증 3개는 서로 독립인 실행 12개다. 사람이 첫 줄에 `ultracode` 를 친다. 코어 빌드에는 쓰지 않는다.
  - 루프 **/loop ON** — 데이터셋당 재랭킹이 최대 30분 돌아 외부 대기가 길다. 간격 20분 이상. 판정은 검증자 판단이라 `/goal` 은 쓰지 않는다.
- 턴 종료 규약: 텍스트만 있는 턴 종료는 완료가 아니다. 종료 조건 미달이고 라운드 상한 전이면 남은 체크리스트 항목을 다시 적고 이어 간다. 사람 입력 없는 자동 재개는 연속 2회까지 — 그 뒤엔 멈추고 남은 항목을 보고한다.
- 서브에이전트 보고는 **30줄 이내**. 코드·로그 전체를 부모 컨텍스트로 올리지 말고 파일 경로와 결론만. 검증자·심사자는 **포그라운드로** 호출해 판정을 받은 뒤 다음 단계로 간다 — 백그라운드로 띄우고 턴을 끝내면 `-p` 에서는 세션이 거기서 끝난다.
- 판정문은 `verdicts/round-N.md`. 다음 라운드에는 **실패 항목만** 넘기고, 통과 항목의 근거는 다시 읽지 않는다.
- 라운드마다 커밋한다 (`round N: <한 줄 요약>`).
- 검증 증거 범위: 재현 2회 결정성 · 누수 점검 · 기준선 공정성 · 반증 3개 이상 · 3시드 신뢰구간 · 비용 표 · 블라인드 비교

## 검증

만드는 에이전트와 **별개의** 검증을 둔다. 자기가 만든 걸 자기가 채점하지 마.
`mp-verifier` 를 매 라운드 새 컨텍스트로 띄운다. 판정은 아래 커맨드로 얻은 증거만.
검증자는 체크리스트를 읽기 **전에** 주제 한 줄("교차 인코더 재랭킹을 넘는 새 재랭킹 방법")만 아는 사용자로서 결과물을 써 본다 (콜드 패스). 기대했는데 안 되는 것이 **기본기 누락**이다.
보고 범위는 **아래 체크리스트 항목과 정확성 결함·기본기 누락으로 한정**한다 — 새 컨텍스트 리뷰어는 결과가 멀쩡해도 뭔가를 보고하는 경향이 있다. 취향 지적은 판정에 넣지 않는다. 근거 없는 pass 는 무효다.

**직접 증거를 확보한 뒤 판정해라. 추정하지 마라.**

```
검증자는 보고된 숫자를 믿지 마라. 직접 실행해서 재현한 값만 근거로 인정한다.

1. 재현: python run.py --dataset scifact --seed 0 을 그대로 두 번 돌려 nDCG@10 과 결정성을 확인한다.
2. 누수 점검: 학습 코퍼스와 평가 문서의 중복을 해시로 대조해 0건임을 보인다.
3. 기준선 공정성: BM25 파라미터가 표준값이고 후보 수가 양쪽 동일한지 확인한다.
4. 반증 시도: 다른 시드 · 후보 수 변경(100→50) · 쿼리 부분집합 3가지. 무너지면 보고한다.
5. 계산 비용(GPU 시간)을 표로 보고한다.
6. mp-judge 에게 이름을 가린 두 리포트(새 방법 / MiniLM 재현)를 주고 5축 100점으로 채점하게 한다.
```

체크리스트 — 전 항목 Yes 여야 통과:

- [ ] 앞서기: MiniLM 교차 인코더 재랭킹에는 없는 질의별 후보 수 적응이 있고, 같은 nDCG@10(±0.005)에서 GPU 시간이 절반 이하임이 비용 표로 확인되는가
- [ ] 기본기: 주제만 들은 사람이 설명 없이 기대할 것(재현 커맨드 하나로 끝까지 도는가, 리포트에 기준선과 새 방법이 같은 표에 있는가, 실패한 시도가 적혀 있는가)이 실제로 돌려 봐서 전부 되고, 콜드 패스의 기본기 누락이 0건인가
- [ ] BM25 기준선 재현값이 보고값과 ±0.01 이내인가
- [ ] 학습·평가 문서 중복이 해시 대조로 0건인가
- [ ] 기준선과 새 방법의 후보 수·지표 구현이 동일한가
- [ ] 시드 고정 후 동일 커맨드 2회 실행 결과가 일치하는가
- [ ] 3시드 평균과 95% 신뢰구간이 데이터셋별 표로 남았는가
- [ ] 새 방법의 핵심 요소를 제거한 ablation 에서 비용 이득이 실제로 사라지는가

판정문 `verdicts/round-N.md` 형식:

- 항목별 **pass/fail 과 근거**(측정값·라인 번호·종료 코드).
- **수용된 제약**: 과제 전제상 원리적으로 해결 불가능한 지적은 실패가 아니라 여기에 적는다. 실패로 세면 정체 감지가 잘못 발동한다.
- 남은 격차가 **요구사항 자체에서 강제된 것인지** 한 문단. 개선이 없으면 없다고 판정한다.
- 점수는 보조 신호다. 항목별 판정과 근거가 1차 결론이다.

## 종료 조건

아래 중 하나에 도달하면 종료 · 최대 5라운드.

(A) 입증: 체크리스트 전 항목 Yes + 3개 데이터셋 중 2개 이상에서 3시드 95% 신뢰구간 기준 비용 절반 이하·nDCG@10 동등 + 블라인드 비교 80점 이상
(B) 기각: 체크리스트 전 항목 Yes + 위 조건 미달이 재현 가능하게 확인됨 → 정당한 종료다. 무엇을 시도했고 왜 안 됐는지 보고한다. 숫자를 만들려고 라운드를 더 태우지 마라.

미달이면 지적된 항목만 다시 만들어 재검증한다. 5라운드까지 못 닿으면 멈추고 남은 항목과 이유를 보고한다.

검증자의 **판정**은 받아들이되 **처방**은 체크리스트 전체와 대조한다 — 한 항목을 고치며 다른 항목을 깨는 교환은 손해다.
같은 지적이 3라운드 연속 반복되면 접근이 틀린 것이다. 멈추고 보고한다 (수용된 제약은 세지 않는다).
