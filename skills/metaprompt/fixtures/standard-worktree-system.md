# 목표

`api/search` 엔드포인트의 응답 지연을 줄여줘. **p99 180ms 이하** 수준이어야 한다.
스택·런타임·의존성 버전은 현행 그대로 유지한다.

"빨라진 것 같다"가 아니라 "같은 부하 프로파일에서 p99 가 180ms 이하로 계측되는 수준"이 목표다.
p99 가 목표에 닿아도 오류율이 올라가거나 응답이 달라지면 실패다.

## 기준점 상세

- 현행 p50 74ms / p95 310ms / p99 812ms (동시성 64, 5분 유지, 워밍업 60초 제외)
- 현행 처리량 1,240 rps, 오류율 0.02%
- 프로파일 결과 전체 시간의 61% 가 `build_facets()` 의 중복 집계에 있음
- 피크는 오전 9시대, 동시성 90, 짧은 쿼리에 분포가 몰림
- 같은 스택의 공개 벤치마크에서 유사 워크로드 p99 중앙값 150~200ms
