# template — 프롬프트 조립 틀

1. 섹션 순서를 바꾸지 않는다. `{{ }}` 는 전부 채운다 (남으면 `check_prompt.py` 가 거부한다).
2. `[[조건]] … [[/조건]]` 은 맞을 때만 남기고 표식 줄은 지운다. 조건: `creative` · `precise` · `lite` · `standard+` · `max` · `worktree` · `greenfield`.
3. M · K · S · 역할 행 · 스위치 조건은 `contract.md` 에서만 가져온다. `--rounds N` 은 M 만 덮어쓴다.
4. 역할 표에는 이 경로·티어가 실제로 쓰는 행만, contract 의 model·effort 그대로. 모델 ID(`claude-…`)를 쓰지 않는다.

## 실행 예산 (route: {{route}} · tier: {{tier}})

- 메인 세션 effort **{{메인 effort}}** · model **{{메인 model}}** — `claude --model {{메인 model}} --effort {{메인 effort}}` 로 시작한다 (도중에는 `/effort {{메인 effort}}`). 세션 모델이 다르면 시작하지 말고 알린다. xhigh·max 는 이득을 실측하지 않았으면 쓰지 않는다.
- 라운드 상한 **{{M}}**. [[standard+]]팬아웃 서브에이전트는 동시에 최대 **{{K}}개**.[[/standard+]][[lite]]팬아웃 없음 — 빌더는 메인 세션 하나다. 혼자 끝낼 수 있는 일을 위임하지 마라.[[/lite]]

## 순차로 진행할 것 (쪼개지 마)

[[precise]]
1. **빨강 먼저** — `{{테스트 경로}}` 에 증상·명세를 검사하는 회귀 테스트를 쓰고, 고치기 전에 `{{테스트 커맨드}}` 가 exit ≠ 0 임을 확인해 `round 0: red` 로 커밋한다. 그 SHA 를 판정문에 적는다.
2. 이후 `{{테스트 경로}}` 는 수정하지 않는다 — `git diff <red SHA>..HEAD -- {{테스트 경로}}` 가 비어야 한다. 테스트가 틀렸다고 판단되면 멈추고 보고한다.
3. 원인 지점을 고친다 → `{{테스트 커맨드}}` exit 0 → `{{회귀 커맨드}}` exit 0.

외부 리서치는 하지 않는다 — 기준점은 base commit 과 명세다.
[[/precise]]
[[lite]]아래 전부를 메인 세션이 순서대로 처리한다. 이 티어는 이음매를 다시 붙일 예산이 없다.[[/lite]]
{{코어 항목}}은 한 에이전트가 처음부터 끝까지 맡아.
이유: {{공유 상태 — 무엇에 같이 쓰는지}}. 쪼개면 부분별로는 그럴싸해도 이음매에서 버그가 난다.

## 검증

만드는 에이전트와 **별개의** 검증을 둔다. 자기가 만든 걸 자기가 채점하지 마.
[[creative]]
`mp-verifier` 를 매 라운드 새 컨텍스트로 띄운다. 판정은 아래 커맨드로 얻은 증거만.
검증자는 체크리스트를 읽기 **전에** 주제 한 줄("{{주제}}")만 아는 사용자로서 결과물을 써 본다 (콜드 패스). 기대했는데 안 되는 것이 **기본기 누락**이다.
[[/creative]]
[[precise]]
1차 판정은 먼저 잠긴 테스트의 종료 코드다 — 만든 쪽이 테스트를 바꿀 수 없다. `/goal` 평가자가 턴마다 출력을 읽고, 마지막 라운드에 `mp-verifier` 가 한 번 새 컨텍스트로 정확성만 본다: 테스트가 명세를 실제로 검사하는가, diff 가 증상만 가리는가.
[[/precise]]
보고 범위는 **아래 체크리스트 항목과 정확성 결함[[creative]]·기본기 누락[[/creative]]으로 한정**한다 — 새 컨텍스트 리뷰어는 결과가 멀쩡해도 뭔가를 보고하는 경향이 있다. 취향 지적은 판정에 넣지 않는다. 근거 없는 pass 는 무효다.

[[worktree]]
근거는 **base commit `{{SHA}}` 대비 diff 와 실제 실행 결과**뿐이다. 커밋 메시지와 만든 쪽의 자기 보고는 근거가 아니다.

    git diff {{SHA}}...HEAD
    {{회귀 커맨드}}
[[/worktree]]

**직접 증거를 확보한 뒤 판정해라. 추정하지 마라.**

[[worktree]]
회귀 통 — 체크리스트와 **별도로** 전 항목 Yes 여야 한다:

- [ ] base commit `{{SHA}}` 에서 통과하던 것이 전부 통과하는가 (`{{회귀 커맨드}}` exit 0)
- [ ] `git diff --stat {{SHA}}...HEAD` 의 변경 파일이 전부 범위 안인가
- [ ] 변경된 공개 인터페이스의 호출부가 전부 갱신됐는가 (`grep` 결과로)
- [ ] {{도메인 레퍼런스가 정한 회귀 항목}}
[[/worktree]]

체크리스트 — 전 항목 Yes 여야 통과:

[[precise]]
- [ ] 회귀 테스트가 red 커밋에서 exit ≠ 0, HEAD 에서 exit 0 인가 (`{{테스트 커맨드}}`)
- [ ] red 이후 `{{테스트 경로}}` 의 diff 가 0줄인가
[[/precise]]
[[creative]]
- [ ] 앞서기: {{기준점}}에는 없는 {{무엇}}이 있고, {{증거 방법}}으로 확인되는가
- [ ] 기본기: 주제만 들은 사용자가 설명 없이 기대할 동작({{주제에서 뽑은 3~5개 — 하한}})이 실제로 써 봐서 전부 되고, 콜드 패스의 기본기 누락이 0건인가
[[/creative]]
- [ ] {{나머지 항목 — 총 개수는 contract 의 C. 전부 Yes/No}}

판정문 `verdicts/round-N.md` 형식:

- 항목별 **pass/fail 과 근거**(측정값·라인 번호·종료 코드).
- **수용된 제약**: 과제 전제상 원리적으로 해결 불가능한 지적은 실패가 아니라 여기에 적는다. 실패로 세면 정체 감지가 잘못 발동한다.
- 남은 격차가 **요구사항 자체에서 강제된 것인지** 한 문단.
[[creative]]- 점수는 보조 신호다. 항목별 판정과 근거가 1차 결론이다.[[/creative]]

## 종료 조건

[[creative]]{{종료 지표 — 도메인 레퍼런스 4절의 티어 문장}} · 최대 {{M}}라운드.[[/creative]]
[[precise]]`{{테스트 커맨드}}` 와 `{{회귀 커맨드}}` 의 종료 코드 0 · 잠금 diff 비어 있음 · 체크리스트 전 항목 Yes · 최대 {{M}}라운드.[[/precise]]
미달이면 지적된 항목만 다시 만들어 재검증한다. {{M}}라운드까지 못 닿으면 멈추고 남은 항목과 이유를 보고한다.

검증자의 **판정**은 받아들이되 **처방**은 체크리스트 전체와 대조한다 — 한 항목을 고치며 다른 항목을 깨는 교환은 손해다.
같은 지적이 {{S}}라운드 연속 반복되면 접근이 틀린 것이다. 멈추고 보고한다 (수용된 제약은 세지 않는다).
