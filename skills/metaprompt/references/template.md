# template — 프롬프트 조립 틀

조립 규칙 세 가지.

1. 섹션 순서를 바꾸지 않는다. 기준점이 맨 앞이어야 이후 판단이 그쪽을 향한다.
2. `{{ }}` 는 전부 채운다. 하나라도 남으면 `check_prompt.py` 가 거부한다.
3. `[[조건]] … [[/조건]]` 블록은 조건에 맞을 때만 남기고, 아니면 통째로 뺀다.
   표식 줄 자체도 출력에 남기지 않는다. 조건: `lite` · `standard+`(standard 와 max) · `max` · `worktree` · `greenfield`.

티어 수치 (SKILL.md 티어 표와 같아야 한다):

| | lite | standard | max |
|---|---|---|---|
| M 라운드 상한 | 2 | 3 | 5 |
| K 동시 팬아웃 | 0 | 3 | 5 |
| S 정체 판정 연속 라운드 | 2 | 2 | 3 |

`--rounds N` 이 오면 M 만 덮어쓴다.

## 작업 격리

이 작업은 `{{worktree 경로}}` 안에서만 한다.
브랜치 `{{브랜치명}}` · base commit `{{SHA}}` · 기준 브랜치 `{{기준 브랜치}}`.

깨면 안 되는 바닥: base commit 시점에 통과하던 것은 전부 그대로 통과해야 한다.
확인 커맨드: `{{테스트 커맨드}}`

아래는 worktree 밖의 공유 상태다. **건드리지 마라.**

- `git push`, 태그 생성, `{{기준 브랜치}}` 로의 병합
- 실제 DB·마이그레이션 실행, 외부 API 쓰기 호출
- `.env`, 로컬 설정, 빌드·패키지 캐시, 전역 패키지 설치
- {{이 저장소·도메인에서 추가로 금지할 것 — 포트·공유 캐시·측정 중 다른 빌드 등}}

건드려야만 목표에 도달할 수 있다면 **멈추고 보고해라.** 임의로 진행하지 마라.
[[/worktree]]

## 실행 예산 (tier: {{tier}})

- 라운드 상한 **{{M}}**. [[standard+]]팬아웃 서브에이전트는 동시에 최대 **{{K}}개**.[[/standard+]][[lite]]팬아웃 없음 — 빌더 하나, 검증자 하나.[[/lite]]
- 서브에이전트 보고는 **30줄 이내**로 받아라. 코드·로그·스크린샷 전체를 부모 컨텍스트로 올리지 마라.
  상세는 파일에 두고 경로와 결론만 보고한다. 컨텍스트가 길어질수록 뒤 라운드의 판단이 흐려진다.
- 검증자 판정문은 `verdicts/round-N.md` 에 저장한다. 다음 라운드 작업 지시는 **실패 항목만** 추려서 넘긴다.
  통과 항목의 근거는 다시 읽지 않는다.
- 라운드마다 커밋한다 (`round N: <한 줄 요약>`). 커밋이 없으면 중간 상태 복원도, 개선 전후 비교도 못 한다.
[[max]]- 모델: 코어 빌드와 검증자는 세션 기본 모델. 리서치·문서·보조 팬아웃은 sonnet 급으로 충분하다.[[/max]]
- 검증 증거 범위: {{증거 범위 — 도메인 레퍼런스의 티어별 세트를 한 줄로}}

[[standard+]]

## 순차로 진행할 것 (쪼개지 마)

[[lite]]아래 전부를 빌더 하나가 순서대로 처리한다. 병렬화하지 마라 — 이 티어는 이음매를 다시 붙일 예산이 없다.[[/lite]]
{{코어 항목}}은 한 에이전트가 처음부터 끝까지 맡아.
이유: {{공유 상태 — 무엇에 같이 쓰기를 하는지}}
여기를 병렬로 쪼개면 부분별로는 그럴싸해 보여도 이음매에서 버그가 난다.

## 검증

만드는 에이전트와 **별개의** 검증 에이전트를 둬. 자기가 만든 걸 자기가 채점하지 마.
검증자는 아주 가혹한 비평가여야 하고, 기본 태도는 거부다.

[[worktree]]
검증자는 **base commit `{{SHA}}` 대비 diff 와 실제 실행 결과물**만 근거로 삼아라.
라운드 커밋 메시지와 만든 에이전트의 자기 보고는 근거가 아니다.

    git diff {{SHA}}...HEAD
    {{테스트 커맨드}}
[[/worktree]]

**검증자는 다음 방법으로 직접 증거를 확보한 뒤 판정해라. 추정하지 마라.**

{{증거 획득 블록 — 도메인 레퍼런스 3절을 티어에 맞게. 실제 커맨드 포함}}

[[worktree]]
회귀 통 — 도메인 항목과 **별도로** 전 항목 Yes 여야 한다:

- [ ] base commit `{{SHA}}` 에서 통과하던 것이 전부 그대로 통과하는가 (`{{테스트 커맨드}}`)
- [ ] `git diff --stat {{SHA}}...HEAD` 의 변경 파일이 전부 이 주제의 범위 안인가
- [ ] 변경된 공개 인터페이스의 호출부가 저장소 전체에서 갱신됐는가 (`grep` 결과로 보여라)
- [ ] {{도메인 레퍼런스가 정한 회귀 항목 1개}}
[[/worktree]]

체크리스트 — 전 항목 Yes여야 통과:

- [ ] {{항목 — lite 4~5개 · standard 6~7개 · max 7~8개. 전부 Yes/No 로 답할 수 있어야 한다}}

검증자는 아래 형식으로 `verdicts/round-N.md` 에 남겨라.

- 항목별 **pass/fail 과 근거**(측정값·라인 번호·재현된 수치). 근거 없는 pass 는 무효다.
- **수용된 제약**: 이 과제의 전제상 원리적으로 해결 불가능한 지적은 실패가 아니라 여기에 적어라.
  실패로 집계하면 정체 감지 규칙이 잘못 발동한다.
- 남은 격차가 **요구사항 자체에서 강제된 것인지** 한 문단으로 답해라.
- 점수는 보조 신호다. 항목별 판정과 근거 수치가 1차 결론이다.

## 종료 조건

{{종료 지표 — 도메인 레퍼런스 4절의 티어별 문장}} · 최대 {{M}}라운드.
미달이면 지적된 항목만 다시 만들어서 재검증해.
{{M}}라운드까지 통과 못 하면 멈추고, 남은 미달 항목과 그 이유를 보고해.

검증자의 **판정**은 받아들이되 **처방**은 체크리스트 전체와 대조해라. 한 항목을 고치려다 다른
항목을 깨는 제안이 나올 수 있다. 통과 조건은 전 항목 Yes이므로 그런 교환은 손해다.

같은 지적이 {{S}}라운드 연속 반복되면 접근 방식이 틀린 것이다. 멈추고 보고해.
(수용된 제약으로 분류된 항목은 이 카운트에서 제외한다.)

## 완료 후

전 항목 Yes 에 도달해도 **병합하지 마라.** 아래를 남기고 멈춘다.

- 브랜치 `{{브랜치명}}` 의 최종 커밋
- 마지막 판정문 `verdicts/round-N.md` (항목별 pass/fail 과 근거 수치, 수용된 제약)
- `git diff --stat {{SHA}}...HEAD` 요약

기준 브랜치가 그사이 움직였으면 최신 `{{기준 브랜치}}` 를 머지한 뒤 **회귀 통만 다시 돌려**
결과를 판정문에 덧붙여라. 여기서 깨지면 전 항목 Yes 가 아니다.

미달로 끝나도 브랜치를 지우지 마라. **병합 여부는 사람이 판정문을 읽고 결정한다.**
[[/worktree]]
[[greenfield]]
## 완료 후

마지막 판정문 `verdicts/round-N.md` 와 최종 커밋을 남기고 멈춘다.
미달로 끝나도 결과물을 지우지 마라. 남은 미달 항목과 이유를 판정문에 적는다.
[[/greenfield]]
