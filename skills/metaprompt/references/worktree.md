# worktree — 이미 있는 저장소에서 한 주제를 끝낼 때

`detect_env.py` 가 `mode: worktree` 를 내거나 `--mode worktree` 가 왔을 때만 읽는다.
template.md 의 `[[worktree]]` 블록이 프롬프트에 들어갈 내용을 갖고 있다. 이 파일은 **무엇을 채우고 왜 그런지**만 다룬다.

## 왜 모드가 따로 있나

빈 디렉터리에서는 깨뜨릴 것이 없었다. 기존 저장소에서는 다르다. 목표만 적으면 받는 모델은 **바닥을 부수면서 올라간다.**
그래서 기준점이 둘이 된다 — 외부 기준점(도달할 목표)과 base commit(깨면 안 되는 바닥). 둘을 한 문장에 섞지 않는다.

| | greenfield | worktree |
|---|---|---|
| 격리 | 빈 디렉터리 + `git init` | `git worktree` + 전용 브랜치 |
| 기준점 | 외부 하나 | 외부 + base commit |
| 체크리스트 | 도메인 통 | 도메인 통 + **회귀 통** (따로 센다) |
| 종료 | 지표 도달 | 지표 도달 = 병합 게이트. 병합은 사람이 |

## 채워야 하는 값 — 전부 detect_env.py 출력에서

| 자리표시자 | 출처 |
|---|---|
| `{{SHA}}` | `head` (전체) — 안내문에는 `head_short` |
| `{{기준 브랜치}}` | `branch` |
| `{{브랜치명}}` | `metaprompt/{{슬러그}}` |
| `{{worktree 경로}}` | `../{{repo_name}}-metaprompt-{{슬러그}}` |
| `{{회귀 커맨드}}` | `commands.test` 첫 항목. 없으면 `ci_run_lines` 에서. 그래도 없으면 **체크포인트에서 묻는다** — 회귀 통이 이 위에 세워지므로 비워 둘 수 없다 |
| `{{테스트 커맨드}}` · `{{테스트 경로}}` (precise) | 빨강 먼저 단계에서 새로 쓸 회귀 테스트 파일과 그것만 돌리는 커맨드 (예: `pytest tests/test_issue_123.py`) |

`dirty_count > 0` 이면 안내문에 "먼저 정리하라"를 넣는다. 더러운 트리에서 worktree 를 파면 기준이 흐려진다.
`warnings` 에 "테스트 커맨드는 찾았지만 런타임이 없다"(예: `npm test` 인데 `node` 없음)가 있으면, 작업 격리 절의 첫 줄에 **사전조건**으로 넣고 안내문에도 한 줄 넣는다. 회귀 통이 돌지 않는 환경에서 루프를 시작하면 첫 라운드가 통째로 낭비된다.

## 저장소 조사 (standard 이상 · `metaprompt:scout` 1개)

외부 조사와 **같은 메시지에서 동시에** 띄운다. 조립할 때는 저장소 사실이 외부 사실보다 우선한다 — 건너뛰면 받는 모델이 이미 있는 것을 다시 만든다. 반환 20줄 이내, 줄당 120자 이내:

- 테스트 스위트의 실제 통과 상태 (지금 깨져 있는 것이 있으면 그것은 회귀가 아니다 — 프롬프트에 적는다)
- 이 주제와 겹치는 기존 모듈·컴포넌트·스크립트 (재사용 대상)
- 컨벤션 한 줄 (린트·포맷·디렉터리 구조)
- 도메인 레퍼런스 6절이 추가로 요구하는 것 (product: 디자인 토큰·컴포넌트 / research: 데이터 캐시 경로·실험 추적 / system: 벤치 하니스·포트)
- 금지 목록에 더 넣을 경로

lite 는 서브에이전트 없이 `detect_env.py` 출력만 쓴다 (위임보다 같은 모델이 직접 읽는 편이 싸다). 대신 프롬프트 첫 순차 항목에 "기존 모듈 조사 후 재사용" 을 넣는다.

## 회귀 통

도메인 통 예산(항목 수) 과 **따로 센다.** 회귀 항목을 도메인 통 안에 밀어 넣으면 도메인 항목이 밀려나고 상충 위험이 커진다.
기본 3항목 + 도메인 레퍼런스 6절의 1항목. 줄이지 않는다. lite 도 같다 — 바닥은 티어와 무관하다.

동시 만족 가능성 점검은 회귀 통까지 포함한다. 도메인 목표가 회귀 통과 상충하면(목표 수치가 기존 API 시그니처를 바꿔야만 나온다)
두 번째 체크포인트(없으면 초안 요약)에서 사용자에게 보인다. 받는 모델이 조용히 한쪽을 포기하게 두지 않는다.

## worktree 가 막아 주지 못하는 것

파일은 갈라졌지만 아래는 부모 저장소와 하나다. template 의 금지 목록이 기본을 갖고 있고, 도메인·저장소 고유 항목을 더한다.
판단이 애매하면 금지 쪽으로 닫는다.

- 원격 push, 태그, 기준 브랜치 병합 · 실제 DB·마이그레이션·외부 API 쓰기 · `.env`·로컬 설정·캐시 · 포트 점유 · 전역 설치

## 병합 게이트

전 항목 Yes 에 도달해도 프롬프트는 병합하지 않는다. 검증자 판정이 틀렸을 때 기준 브랜치가 오염되면 되돌리기가 훨씬 비싸고,
라운드별 커밋(개선 전후 비교 근거)이 squash 로 사라지는 것도 손해다. 사람이 판정문의 회귀 통부터 읽고 결정한다.
