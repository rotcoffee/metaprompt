# 실측 장부 — metaprompt lite 는 채팅보다 나은가 (2026-09-30 ~ 10-01)

H1–H4 는 예측과 반증 조건을 실행 전에 적었다 (아래 표의 "사전 기준"). 나머지는 실험 도중 세운 것이다. 확인은 헤드리스 세션(`claude -p`)과 블라인드 채점 에이전트로 했다.
헤드리스 세션(r01–r08)은 전부 opus · `--effort medium` · `acceptEdits` · 빈 디렉터리이고 비용은 `total_cost_usd` 다. "사용자 실행" 행은 대화형 세션(권한 모드 auto)이고 비용은 세션 기록의 토큰에 단가를 곱한 추정값이다.
채점 기준은 결과물을 보기 전에 확정했고, 채점자는 이름표만 봤다.
원자료(세션 JSON · 결과물 · 채점기 · 스크린샷)는 저장소 밖 `~/work/bench-lab/`, `~/work/bench-sortviz/`, `~/work/bench-sheet/` 에 있다 — 여기엔 수치만 옮긴다.

## 진단 — lite 0.3.0 이 기본기를 빠뜨린 경로

- 시작 커맨드에 `--model` 이 없어 실행 세션이 계정 기본 모델로 떴다.
- 빌더는 프롬프트에 적힌 것만 만들었다. 적힌 수치("최소 20–100")가 상한이 됐고, "좁은 폭은 범위 밖"이라고 적힌 축이 깨졌고, 적히지 않은 저장 · 숫자 해석 · 원소별 확정 표시가 빠졌다.
- 빌더가 제품 의미를 검증 프로브에 맞췄다 ("검증 지시서의 'Bubble 교환 28' 이 그대로 나오게 한 선택").
- 검증자는 빌더가 이미 돌린 프로브를 다시 돌렸다. 실제 클릭 · 새로고침 · 좁은 폭은 0회, 새로 찾은 결함 0건.
- 생성 프롬프트에서 제품 명세는 12–14% 줄, 검증 장치가 51–63% 줄이었다.
- 채팅 빌더는 시키지 않아도 헤드리스 브라우저로 스스로 시험했다.

## 스킬에 반영한 것

1. 라우팅: 그린필드 · 파일 1~2개 · 출시/공개/기준점 신호 없음 → skip. 크기가 creative · precise 신호보다 먼저다.
2. creative 체크리스트에 `기본기:` 항목, 프롬프트에 "명세가 아니라 바닥" 선언, "범위 밖" 문장과 제품 안 검증용 훅 금지.
3. 검증자 콜드 패스: 체크리스트를 읽기 전에 주제만 아는 사용자로서 실제 입력으로 써 본다.
4. 시작 커맨드에 `--model opus`.
